# Tool-redundancy matrix

An empirical answer to "how correlated are the 31 non-submit toolbox tools' outputs with each other", computed
directly from `finagent.harness.toolbox`'s own tool functions and `finagent.data.pit.NewsCache`, called exactly
as the harness calls them, walked day by day over real point-in-time price and news history for all 96
`data/pit_cache` tickers (not just the pilot's six). No model calls, no hand-waving about which tools "must" be
redundant — every number below is measured. Ported from
`1_overreaction/repro/evidence_relations/tool_redundancy_{generate,analyze}.py`.

Generated by `finagent.evidence_relations.tool_redundancy.generate` (pulls the raw features) and `...analyze`
(pure pandas correlation + summary tables). Both are deterministic and re-run to byte-identical output (verified
by running the whole pipeline twice and diffing every output file — see the report).

## Which tools were run, and which were excluded

`finagent.harness.toolbox.TOOLS` lists 31 available non-submit tools. 8 are excluded here because their numeric
output depends on account/session state (a simulated portfolio or trade history), not on price/news:

`get_calibration_ledger, get_lessons, get_portfolio, get_trade_history, memory_read, memory_search, memory_write, simulate_order`

The remaining **23** tools were called for every (ticker, day):

`get_daily_candles, get_weekly_candles, get_monthly_candles, get_returns, get_price_stats, get_trend_signal, get_mean_reversion_signal, get_rsi, get_macd, get_volatility_stats, get_support_resistance, get_volume_analysis, get_risk_budget, get_kelly_sizing, get_drawdown_stats, get_earnings_calendar, get_event_risk, get_news, search_news, get_news_stats, get_macro_news, get_insider_trades, get_insider_summary`

Each call used one **fixed** argument dict for every ticker/day (so any variation we measure reflects the
underlying data, never a query-parameter choice): `{"query": "earnings", "note": "test", "expected_return_pct":
0.3, "expected_vol_pct": 1.5, "action": "buy", "target_exposure_pct": 40, "ticker": <the day's ticker>}`. Tools
not needing an argument just used their own default. Every call used a **fresh** account state
(`toolbox.new_state()`): no simulated portfolio or trade history carried across days.

## Numeric-field convention (what counts as a column)

For each tool's parsed JSON output: nested dicts are flattened recursively (`tool.path.to.field`); a leaf is kept
as a column only if it is `int`/`float` (`bool`, `None` and strings — including every categorical
`signal`/`regime` label — are excluded, by design: this is a matrix of *continuous* information overlap, not of
label agreement). Lists are not auto-flattened; five tools return a bare list or a dict whose only real content is
a list (`get_daily_candles`, `get_weekly_candles`, `get_monthly_candles`, `get_news`, `get_insider_trades`), plus
`get_support_resistance`'s variable-length support/resistance levels — for these, a small, explicit set of derived
scalars was added, every one suffixed `__derived`. Full rationale and code:
`tool_redundancy/generate.py::flatten_numeric` and `derive_extra`.

## Top 20 most correlated (tool, field) pairs, and clusters

Full tables: `top_correlated_pairs.csv`, `clusters.csv`. The headline result — a large cluster of near-duplicate
"today's close price" columns across several tools, confirmed byte-identical in membership to the source's own
cluster 0 (same 22 fields):

`get_daily_candles.head0_close__derived`, `get_daily_candles.head0_high__derived`, `get_daily_candles.head0_low__derived`, `get_daily_candles.head0_open__derived`, `get_mean_reversion_signal.bollinger_lower`, `get_mean_reversion_signal.bollinger_upper`, `get_mean_reversion_signal.close`, `get_monthly_candles.head0_close__derived`, `get_monthly_candles.head0_high__derived`, `get_monthly_candles.head0_low__derived`, `get_monthly_candles.head0_open__derived`, `get_price_stats.close`, `get_price_stats.high_52w`, `get_support_resistance.close`, `get_trend_signal.close`, `get_trend_signal.ema21`, `get_trend_signal.ema55`, `get_trend_signal.ema8`, `get_weekly_candles.head0_close__derived`, `get_weekly_candles.head0_high__derived`, `get_weekly_candles.head0_low__derived`, `get_weekly_candles.head0_open__derived`

Note on the "~10 tools" figure some earlier write-ups (including the ask that produced this report) give for this
cluster: the cluster's own membership — reproduced here identically to the source — spans **7**
distinct tools (get_daily_candles, get_mean_reversion_signal, get_monthly_candles, get_price_stats, get_support_resistance, get_trend_signal, get_weekly_candles), not 10. This port does not adjust that number: it reports what the
clustering (|Pearson r| >= 0.9, connected components) actually finds, which matches the source's own
`clusters.csv` row for row.

## Tool-level verdict (tool x tool pairs, cross-tool field pairs only, n >= 1000)

- **0 pairs are fully redundant** (no two tools are redundant in *every* field).
- **42 pairs are fully independent** (every field pair |r|<0.2 both ways) — the candidate set for an
  "independent condition" elsewhere in this project. Reproduced here as the IDENTICAL set of 42 tool
  pairs as the source (checked tool-pair-for-tool-pair, see the report).
- **94 pairs are mixed**.

Full table: `tool_pair_summary.csv`.

## Reproducibility

CPU only, no network, no model calls. No randomness: every ticker (all 96) and every trading day in the
news window is used — an exhaustive walk, not a sample. Rerun with:

```
cd finance1
.venv/bin/finagent evidence-tools --workers 32
```
